# WPT summary data format

This directory contains a compact time series of Blitz's Web Platform Test
scores: one data point per tested Blitz commit, for every folder of the WPT
tree that has been run. It is generated by `scripts/process` from the raw
reports in `reports/` and consumed by the charts on
[blitz.is](https://blitz.is/status/wpt).

## Layout

```text
summary/
  runs.json                 # shared per-run metadata (one entry per run)
  areas/
    css.json                # scores for the whole "css" suite
    css/
      css-flexbox.json      # scores for "css/css-flexbox"
      css-flexbox/
        alignment.json      # scores for "css/css-flexbox/alignment"
      ...
```

There is **one file per WPT folder** ("area"), stored at
`areas/<area path>.json`. Future top-level suites (e.g. `html`) would appear
as `areas/html.json` plus an `areas/html/` directory.

## `runs.json`

Metadata shared by all area files, stored once:

```json
{
"runs":[
{"date":"2025-04-22T20:28:42Z","wpt_revision":"42a9dfcc6","product_revision":"3fe93c9c...","commit_message":"fix: loading style resources (#208)"}
]}
```

| Field | Meaning |
| --- | --- |
| `date` | Timestamp of the Blitz commit (RFC 3339). Falls back to the WPT run's start time if the commit isn't found. |
| `wpt_revision` | Revision of the WPT test suite that was run (9-char sha). |
| `product_revision` | The Blitz commit that was tested (full sha). |
| `commit_message` | First line of the Blitz commit's message (optional). |

Runs are sorted by `(date, product_revision)`.

## Area files (`areas/<area path>.json`)

Each area file contains a single `scores` array with **one entry per run,
index-aligned with `runs.json`** (entry *i* belongs to run *i*):

```json
{
"scores":[
[23972,8658.8,33098,10907],
null,
[23980,8672.8,33112,10921]
]}
```

Each entry is either `null` (the area has no data for that run) or a 4-tuple:

```text
[total_tests, total_score, total_subtests, total_subtests_passed]
```

| Index | Meaning |
| --- | --- |
| 0 | Number of tests run in this area |
| 1 | Servo-style score (sum over tests of the fraction of subtests passed), rounded to 1 decimal place |
| 2 | Number of subtests run |
| 3 | Number of subtests passed |

The subtest pass percentage charted on the website is `scores[3] / scores[2]`.

Tests with status `SKIP` are stripped before scoring, so all counts are
relative to the tests Blitz can actually run.

## Formatting and update model

All files are plain JSON, written with one run per line so that importing a
new run produces a one-line diff in every file. A new run appends one entry
to `runs.json` **and to every area file simultaneously** — the files always
change together and always have the same number of entries. Consumers can
therefore cache the whole dataset keyed on `runs.json` (e.g. its ETag) and
revalidate only that one file.

## Published artifacts

The `Process WPT Results` workflow publishes this directory to GitHub Pages
on every update, along with `summary.tar.zst` — a zstd-compressed tarball of
the entire `summary/` directory (raw reports are not included).
